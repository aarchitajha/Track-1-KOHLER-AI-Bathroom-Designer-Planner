# KOHLER AI Bathroom Designer & Planner

An interactive AI design assistant that turns a customer's room dimensions, budget, and aesthetic preference into optimized, real Kohler product bundle recommendations — visualized in an accurate 3D room, refinable through natural conversation, and viewable in AR on both Android and iOS.



---

## What it does

1. **Input** your bathroom dimensions, budget, and aesthetic theme (Minimalist Modern, Classic Luxury, or Japanese Zen) — or upload a photo/rough sketch and let AI vision estimate the room for you.
2. **Get 3 optimized suites** — Budget-Optimized, Balanced Signature, and Artisan Luxury — generated by a multi-constraint optimization engine using real, verified Kohler India catalog products, respecting spatial clearances and MEP (plumbing/electrical) constraints.
3. **Refine through conversation** — chat naturally to swap fixtures, change the aesthetic, or adjust budget, and watch the 3D scene update live.
4. **Visualize in 3D or 2D** — a realistic, procedurally generated room with real Kohler product models, or a scaled 2D architectural floor plan with clearance validation.
5. **View in AR** — see the design in your actual space via WebXR (Android) or Apple AR Quick Look (iOS).
6. **See your water savings** — every suite includes EPA WaterSense-equivalent conservation metrics and estimated annual savings.
7. **Export an official quote** — a branded, itemized PDF with pricing, specs, and sustainability metrics.

## Tech Stack

**Frontend**
- React 19 + Vite 8
- React Three Fiber + Three.js + Drei (3D visualization)
- react-markdown (chat formatting)

**Backend**
- FastAPI + Uvicorn (Python 3.10+)
- SQLAlchemy ORM (PostgreSQL in production, SQLite for local dev)
- ReportLab (PDF generation)

**AI / LLM**

- Local Ollama support (offline/dev mode) with a deterministic intent router for common commands
- Groq (OpenAI-compatible) supported as a free hosted alternative to Ollama in production

**Data**
- Real Kohler India product catalog, collected via a Playwright-based scraper from kohler.co.in, with a `verified` flag ensuring no fabricated product data reaches the app
- 3D/AR assets sourced from official Kohler model libraries (Studio Kohler / BIMobject)

## Getting Started

### Prerequisites
- Python 3.10+
- Node.js 18+ and npm
- A Groq key, Anthropic key, or a local Ollama instance

### 1) Create a Python virtual environment
On Windows PowerShell:
```powershell
cd d:\kohler-track1
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2) Install backend dependencies
```powershell
pip install -r backend\requirements.txt
```

### 3) Configure environment variables
Create or edit `backend/.env` with:
```env
DATABASE_URL=sqlite:///./kohler.db

# Groq (recommended hosted option for this project)
GROQ_API_KEY=gsk_your_key_here
GROQ_MODEL=openai/gpt-oss-120b

# Optional: Anthropic key
# ANTHROPIC_API_KEY=sk-ant-api03-your-actual-key-here

# Optional: local Ollama fallback
# OLLAMA_BASE_URL=http://localhost:11434
# OLLAMA_MODEL=llama3.2
```

> Important: if you previously ran `$env:GROQ_API_KEY=...` in PowerShell, that session-level environment variable can override the value in `.env`. For a clean run, close that terminal and open a fresh one before starting the backend.

### 4) Seed the local catalog database
```powershell
python -m backend.db.load_catalog
```

### 5) Run the backend
```powershell
uvicorn backend.main:app --host 0.0.0.0 --port 8004 --reload
```

Backend health check:
- http://localhost:8004/health

API docs:
- http://localhost:8004/docs

### 6) Run the frontend
In a second terminal:
```powershell
cd d:\kohler-track1\frontend
npm install
npm run dev
```

Frontend URL:
- http://localhost:5173

### 7) Verify the app is running
- Backend health: `http://localhost:8004/health`
- Frontend app: `http://localhost:5173`
- If the chat returns `401 invalid_api_key`, check for a stale `GROQ_API_KEY` in the current PowerShell session and open a fresh terminal before restarting the backend.

## Known Limitations

- iOS Safari does not support WebXR — AR on iOS uses Apple AR Quick Look (`.usdz`) instead, a separate code path from the Android WebXR flow.
- Chat session state is held in memory and resets on backend restart; sketch upload history is persisted to the database and survives restarts.
- Local Ollama inference speed depends on host hardware; a deterministic intent router handles common commands (greetings, budget math, theme switches) without invoking the LLM to keep response times low.
